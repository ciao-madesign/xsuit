# 12 — Security model (anti-abuse)

xsuit must not be usable for attacks, data theft or abuse. Rules below are **enforced by tests** (`tests/security.test.ts`, run in CI), so a future change cannot quietly break them.

## Principles

1. **No code from outside.** No remote scripts, no `eval`/`Function`, no `innerHTML`/`insertAdjacentHTML`/`document.write`. Strict extension CSP (`script-src 'self'`, no inline).
2. **No network.** No `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`, no URLs in code. Nothing leaves the device; exports are local files the user saves.
3. **Least privilege.** Permissions: `storage`, `activeTab`, `scripting`. No site access at install; the user grants one site at a time, **https only**. No `cookies`, `history`, `webRequest`, `downloads`.
4. **Narrow site grants.** Hosts that cover many organizations (`co.uk`, `github.io`, …), IP addresses and malformed names are refused. Stored lists are capped (500).
5. **Pages cannot command the extension.** The page script only answers messages from the extension itself (same id, not from a tab), with a fixed list of message types. Nothing is exposed to web pages (`web_accessible_resources`, `externally_connectable` absent).
6. **Data, not code, drives changes.** Rules/adapters are bundled and validated; CSS effects accept only plain declarations (no `url()`, `@import`, braces, `expression`). Selectors/patterns with unsafe characters are rejected.
7. **Never touch sensitive areas.** Passwords, payment, login, consent, account deletion are protected and skipped.
8. **No bait links.** Shortcuts copy only plain http(s) links: no `javascript:`/`data:`/`blob:`/`file:`, no embedded credentials, nothing inside protected areas, nothing that logs out, deletes, pays, unsubscribes or confirms.
9. **No runaway work.** Loop guard stops the engine if the page keeps changing; guard checks are capped per rule; JSON-LD size is capped.
10. **Reversible and visible.** Every change is journaled and undoable; the on-page label shows when xsuit changed something. Report screenshots are shown only as inline PNG; exported file names are sanitized.

## Misuse through adapters, rules or hostile pages (added 2026-11-10)

**Threat.** Someone uses xsuit as a mask: an adapter or rule (from a contributor, or one day from a user or a server) or a hostile page makes xsuit steer people toward clicks they did not choose, hide a warning, make a credential or payment form look friendlier, or make a scam look "native".

**What stops it.** Each point is enforced by code and tested (`tests/attacks.test.ts`, `tests/security.test.ts`, `tests/integrity.test.ts`).

| Risk                                         | Defence                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adapter aims at things people click          | Adapter selectors may only locate page **blocks**: links, buttons, inputs, frames and `href`/`action`/`onclick`/`download` are refused (only the search box may use a form or input). Over-broad selectors, long lists, slow patterns refused.                                                                                                                                                                                                                                        |
| Adapter gives the wrong role to an element   | An element is accepted as a component only if it plausibly is one (a search box holds an input, a nav holds links, an article has text, never the whole page); otherwise ignored and reported as `implausible`.                                                                                                                                                                                                                                                                       |
| Adapter applied to user-generated pages      | An adapter applies to its **listed host only**, never to subdomains (user sites, blogs, uploads).                                                                                                                                                                                                                                                                                                                                                                                     |
| Unverified adapter overrides recognition     | Draft adapters never override generic recognition (decision #48); only a verified adapter does.                                                                                                                                                                                                                                                                                                                                                                                       |
| Adapters or rules changed silently           | `rules/integrity.json` holds a hash of every rule, effect, source, adapter and schema. CI fails when they differ; `npm run lock` is run only after the diff was read. Rules and adapters are bundled: there is no loading from the network, storage or the user.                                                                                                                                                                                                                      |
| Shortcut strip promotes bad links            | Only links a person can see (not hidden, transparent, tiny or `aria-hidden`), on the **same site**, with plain text (no hidden or bidirectional characters, not looking like another address), not downloads or executables, not actions (log in/out, pay, delete, confirm, accept, subscribe, verify, claim…), not from a block containing a non-search form or a notice. The strip says "xsuit shortcuts", links carry `rel="noopener noreferrer"` and a "Goes to host/path" title. |
| A warning is hidden or buried                | Blocks holding alerts, dialogs or live announcements, non-search forms, file inputs or downloads are never collapsed, moved, grouped, emphasized or used as a source. A container holding such a notice is never reordered.                                                                                                                                                                                                                                                           |
| Credential or payment page made friendlier   | On any page asking for a password, card data or going to checkout/login, only spacing and typography change: no structural change, no emphasis.                                                                                                                                                                                                                                                                                                                                       |
| Page hides xsuit's label to disguise changes | The label cannot be hidden by page CSS (inline `!important`); if the page removes or hides it, xsuit **undoes everything** (checked every 1.5 s). Hiding the label by the user's choice is allowed for spacing/typography only; any structural change forces it visible.                                                                                                                                                                                                              |
| Effects used to overlay or trick             | Effects may not use `position`, `z-index`, `pointer-events`, `cursor`, `content`, `opacity`, `display`, widths, outline removal, animation.                                                                                                                                                                                                                                                                                                                                           |
| xsuit acting for the user                    | Code that runs in pages cannot click, submit, navigate, open windows, dispatch events, touch the clipboard, create forms/inputs/images, or take focus (except inside its own label). Listeners exist only on buttons xsuit creates.                                                                                                                                                                                                                                                   |
| Engine adds something unexpected             | Across all test pages and a hostile adapter, the engine may add only `style, button, div, nav, a, span` and may change page elements only by adding `data-xsuit-*` attributes.                                                                                                                                                                                                                                                                                                        |

**Rule for contributors.** Any new rule action, adapter capability or effect that can add, move, hide or link content needs a matching test in `tests/attacks.test.ts` that shows it cannot be used for the cases above. Loading adapters or rules from outside the package is **not allowed** without a new signed-update design and a written decision.

## Dependencies and releases

CI runs `npm audit --omit=dev` (high severity fails). Dev tools are not shipped. Keep dependencies few; review lockfile changes.

## Not covered / to decide

- Compromise of the developer's account or build pipeline (use 2FA, protected branch, signed releases).
- A scam page that is entirely self-made: xsuit does not judge whether a site is honest. It will not make such a page look more trustworthy through the changes above, but it is not a phishing detector.
- Reporting channel for vulnerabilities (a `SECURITY.md` with a contact is still needed).
