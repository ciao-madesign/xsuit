## Effect catalog (concrete CSS)

Concrete CSS for rule actions. Direction of each effect comes from the evidence cited by the rules that use it. The MAGNITUDE (how much) is a design choice, kept deliberately modest, and must be tuned during the internal review (B11). Effects only use properties that cannot hide content, move elements or shrink targets (checked by tests). Saturation filters CAN lower text contrast (see contrastSimulation, a correction made in B8): every changed element is therefore checked at runtime by the accessibility guard, which undoes a rule that measurably worsens contrast, target size or horizontal scroll.

- `density=compact`: `line-height: 1.4; gap: 0.5rem`
  - Basis: Direction: Chinese homepages show higher visual density and more blocks (li2026); Chinese users prefer relatively high density (nng2016). Magnitude is a design choice.
  - Constraints: Line height stays at or above 1.4 so text remains readable; no font-size change. gap only affects flex/grid containers, so non-grid layouts are untouched.
  - Used by: visual.china.compact-density
- `density=spacious`: `line-height: 1.7; gap: 1.5rem`
  - Basis: Direction: Western homepages show lower visual density and fewer blocks (li2026); weak supporting evidence from nng2016 that foreign participants tolerated simple sites. Magnitude is a design choice.
  - Constraints: No content is hidden; only spacing grows.
  - Used by: visual.western.spacious-density
- `spacing-scale=tight`: `padding-block: 0.5rem`
  - Basis: Direction: less white space on Chinese sites (li2022). Magnitude is a design choice.
  - Constraints: Block padding only; interactive targets keep their own size.
  - Used by: visual.china.tight-spacing
- `spacing-scale=airy`: `padding-block: 1.5rem`
  - Basis: Direction: more white space on Western sites (li2022). Magnitude is a design choice.
  - Constraints: Block padding only.
  - Used by: visual.western.airy-spacing
- `palette-saturation=muted`: `filter: saturate(0.8)`
  - Basis: Direction: Chinese palettes are more saturated and brighter than Western ones (li2026). Magnitude is a design choice.
  - Constraints: Hue is not changed (no red/gold stereotype). Can lower text contrast on some colour pairs (see contrastSimulation): the runtime accessibility guard undoes the rule on any element where contrast measurably gets worse.
  - Used by: visual.western.muted-palette
- `palette-saturation=vivid`: `filter: saturate(1.25)`
  - Basis: Direction: Chinese palettes are wider, more saturated, brighter (li2026), and use more red and blue (li2022). Magnitude is a design choice.
  - Constraints: Saturation only; hue untouched. Can lower text contrast on some colour pairs (see contrastSimulation): the runtime accessibility guard undoes the rule on any element where contrast measurably gets worse.
  - Used by: visual.china.vivid-palette
- `image-prominence=high@img`: `width: 100%; object-fit: cover`
  - Basis: Direction: higher image diversity and visual density on Chinese homepages (li2026). Card-level application is an extrapolation, so this effect is provisional. Magnitude is a design choice.
  - Constraints: Images keep their alt text; no image is hidden or replaced.
  - Used by: visual.china.image-led
- `link-affordance=underlined@a`: `text-decoration: underline`
  - Basis: Direction: more underlined links on Western sites (li2022). Underlining also keeps links identifiable without relying on colour (WCAG 1.4.1).
  - Constraints: Applies to links inside the marked blocks only; buttons and navigation chrome are not blocks the rule targets.
  - Used by: visual.western.underlined-links
- `de-emphasize=medium`: `filter: saturate(0.7)`
  - Basis: Direction: promotions and carousels are more selective in Western designs (li2026 posters 66 vs 99, autoplay 39 vs 99). Weight is reduced through saturation, never opacity (opacity lowers contrast on every pair); saturation can still lower contrast on some pairs, so it is guarded at runtime. Magnitude is a design choice.
  - Constraints: Content stays fully visible and readable; no opacity change. Can lower text contrast on some colour pairs (see contrastSimulation): the runtime accessibility guard undoes the rule on any element where contrast measurably gets worse.
  - Used by: visual.western.quiet-promos, visual.western.quiet-carousel
- `emphasize=medium`: `filter: saturate(1.2)`
  - Basis: Direction: banners, carousels and recommendations carry more weight in Chinese designs (li2026, project synthesis). Magnitude is a design choice.
  - Constraints: Can lower text contrast on some colour pairs (see contrastSimulation): the runtime accessibility guard undoes the rule on any element where contrast measurably gets worse.
  - Used by: visual.china.prominent-promos, visual.china.prominent-carousel, visual.china.discovery-feed
- `emphasize=high`: `outline: 2px solid currentColor; outline-offset: 2px`
  - Basis: Provisional: the rule using it (search first) is a hypothesis. An outline in the text colour marks the element without altering any colour or layout.
  - Constraints: currentColor keeps contrast equal to the text; outline does not affect layout.
  - Used by: visual.western.search-first

Contrast simulation: Share of text/background colour pairs that pass WCAG 4.5:1 and fall below it after the CSS saturate() filter.

- Method: All pairs of a 5x5x5 RGB grid (levels 0, 64, 128, 192, 255) with contrast >= 4.5 before; text and background both filtered (worst case: they belong to the same filtered element). Reproduced by tests/b8.test.ts.
- saturate(0.7): 3.93% of passing pairs fall below 4.5:1
- saturate(0.8): 2.67% of passing pairs fall below 4.5:1
- saturate(1.2): 14.12% of passing pairs fall below 4.5:1
- saturate(1.25): 17.63% of passing pairs fall below 4.5:1
- Correction: Until B7 this file claimed that saturation filters keep luminance and therefore do not lower contrast. That was wrong: the filter works on sRGB values, so relative luminance changes. The claim was removed and the runtime guard added.
- Caveat: Synthetic grid, not real pages; real sites use few distinct colours, so the real share is unknown until B11.

No effect (on purpose):

- `visual-hierarchy=strong`: Rule visual.western.strong-hierarchy is a hypothesis with no direct measurement of visual hierarchy. No effect is invented; it becomes active only when validated.
- `visual-hierarchy=flat`: Rule visual.china.flat-hierarchy links block count to visual weight only by interpretation. No effect is invented until validated.

## Rules

### `visual.china.compact-density` — moderate

- **Action:** Use a compact layout density with more content per screen. (china, visual, risk low)
- **Why:** Chinese homepages show about three times the visual density and nearly twice the main content blocks; NN/G reports Chinese users prefer relatively high information density and perceive complexity through familiarity. It fires only when the measured page is sparser than the midpoint between the two sample means, so pages that are already dense are left alone.
- **Supported by:**
  - `li2026`, Section 2.2 table: visual density 38.21 vs 12.87; main content blocks 5.91 vs 3.14 — Higher density and more blocks on Chinese homepages
  - `nng2016`, Section 'Yes, Chinese Sites Are Often Complex': Chinese participants tolerated complexity and appreciated density, especially on portal and news sites (n=6 Chinese users, 12 total) — Chinese participants prefer fairly high information density (small qualitative study)
- **Does not show:**
  - Sample is institutional (municipal) homepages; commercial sites are not covered.
  - NN/G is small (6 Chinese users): Chinese users also met many usability problems on complex sites and some designs were judged too complicated.
  - Chinese users were less accepting of the simple sites tested, but this is not a test of this transformation.
  - Delta-based: the density threshold (25.54) is the midpoint of two sample means from a study of municipal homepages. It is provisional and compared against our own metric definition, whose scale may differ from the study's. Replace with own measurements (A2).
- **Limits:** Tendency from research, not a universal rule; varies by site and sector. Touch targets must stay usable. Does nothing on pages already at or above the threshold; also does nothing if the page could not be measured.
- **Test results:** none yet

### `visual.china.vivid-palette` — moderate

- **Action:** Increase colour saturation for a livelier look. (china, visual, risk low)
- **Why:** The 2026 study finds Chinese palettes wider, more saturated and brighter, and the 2022 review reports more red and blue. Doc 02 warns against the red+gold stereotype, so this rule changes saturation only, not hue.
- **Supported by:**
  - `li2026`, Section 2.2 other results: Chinese palettes wider, more saturated, brighter — Saturation difference
  - `li2022`, Section 2.1: more red and blue on Chinese sites — Colour usage difference
- **Does not show:**
  - Evidence comes from institutional (municipal) homepages; commercial sites are not covered.
  - No evidence that raising saturation improves experience.
  - Hue is deliberately untouched.
- **Limits:** Tendency from research, not a universal rule; varies by site and sector. Must keep text contrast at or above WCAG AA. Never apply a red/gold stereotype.
- **Test results:** none yet

### `visual.western.spacious-density` — moderate

- **Action:** Use a spacious layout density with more whitespace. (western, visual, risk low)
- **Why:** Western homepages in the sample show about a third of the visual density of Chinese ones and fewer content blocks (2026 study). NN/G found that foreign participants were less annoyed by problems on simple sites than on complex ones. Raising whitespace moves a dense page toward the sparser convention without removing content. It fires only when the measured page is denser than the midpoint between the two sample means, so pages that are already sparse are left alone.
- **Supported by:**
  - `li2026`, Section 2.2 table: visual density 12.87 vs 38.21 per 1,000 px; main content blocks 3.14 vs 5.91 — Lower density and fewer blocks on Western homepages
  - `nng2016`, Section 'Yes, Chinese Sites Are Often Complex': foreign participants less likely to be annoyed by usability issues on simple sites than on complex ones (n=6 expatriates) — Weak support: tolerance of simple sites among non-Chinese participants
- **Does not show:**
  - Sample is institutional (municipal) homepages; commercial sites are not covered.
  - NN/G does not report a general Western preference for simplicity; its non-Chinese participants were 6 expatriates living in China.
  - Search-results and article pages are extrapolations from homepages.
  - Delta-based: the density threshold (25.54) is the midpoint of two sample means from a study of municipal homepages. It is provisional and compared against our own metric definition, whose scale may differ from the study's. Replace with own measurements (A2).
- **Limits:** Tendency from research, not a universal rule; varies by site and sector. Only spacing changes; content must not be hidden. Does nothing on pages already at or below the threshold; also does nothing if the page could not be measured.
- **Test results:** none yet

### `structure.china.surface-shortcuts` — hypothesis

- **Action:** Show a small strip of links to sections that already exist in the main navigation, just above the hero block. (china, structural, risk low)
- **Why:** Chinese homepages show more main content blocks (5.91 vs 3.14 in Li 2026), which suggests more parallel entry points. A strip of links to existing sections makes several entry points reachable near the top without moving or removing anything; that it helps users is a design hypothesis.
- **Supported by:**
  - `li2026`, Section 2.2 table: main content blocks 5.91 vs 3.14 — More parallel content blocks on Chinese homepages
- **Does not show:**
  - Evidence comes from institutional (municipal) homepages; commercial sites are not covered.
  - No evidence that a shortcut strip improves findability.
  - Duplicated links add content; may be redundant where the navigation is already visible.
- **Validation plan:** Internal before/after review on Baidu, Taobao and Bilibili homepages: strip appears only when 3+ safe links exist, original page restores exactly; later check with real users (deferred, decision #8).
- **Limits:** Copies at most 6 existing links (text and address only); never creates new destinations. Skipped when fewer than 3 usable links are found.
- **Test results:** none yet
